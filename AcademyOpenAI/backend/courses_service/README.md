# Courses Service

Микросервис, отвечающий за управление курсами в платформе AcademyOpenAI.

## Назначение сервиса (согласно архитектуре)

Сервис `courses_service` выполняет следующие ключевые функции:

*   **Управление метаданными курсов:** Предоставляет API для создания, чтения, обновления и удаления (CRUD) информации о курсах (название, описание и т.д.).
*   **Обработка контента:** Принимает загружаемые видеофайлы или текстовые материалы, которые будут использоваться для автоматической генерации интерактивного курса.
*   **Запуск конвейеров обработки:** Инициирует фоновые задачи (выполняемые `Pipeline Worker`) для преобразования загруженного контента (видео или текста) в структурированный интерактивный курс.
*   **Хранение данных:** Взаимодействует с базой данных MongoDB для сохранения информации о курсах и их содержимом.

**Входные данные:**
*   HTTP API запросы от API Gateway (Kong) для операций CRUD над курсами.
*   Загружаемые файлы (видео) или текстовые данные через API.

**Выходные данные:**
*   HTTP API ответы с данными курсов или статусом операций.
*   Сообщения (задачи) в очередь сообщений (например, RabbitMQ или Redis Streams) для запуска `Pipeline Worker`.
*   Данные, сохраняемые и извлекаемые из MongoDB.

## Текущее состояние проекта

На данный момент реализована базовая структура FastAPI приложения с основными CRUD эндпоинтами для курсов.

**Основные компоненты:**

*   `app/main.py`: Точка входа FastAPI приложения, настройка CORS, подключение роутеров.
*   `app/api/v1/endpoints/courses.py`: Определения API эндпоинтов для курсов (`/api/v1/courses`).
*   `app/schemas/course.py`: Pydantic модели для валидации данных запросов и формирования ответов (`CourseCreate`, `CourseUpdate`, `CourseResponse`).
*   `app/services/course_service.py`: **(Заглушка)** Содержит логику для работы с курсами. *На данный момент использует временное in-memory хранилище (`_courses_db`) вместо реального взаимодействия с MongoDB.*
*   `app/db/session.py`: **(Заглушка)** Функция-зависимость для получения сессии базы данных. *Сейчас возвращает `None`, так как реальное подключение к БД не настроено.*
*   `app/core/config.py`: Базовая конфигурация приложения (использует `pydantic-settings`).
*   `Dockerfile`: Файл для сборки Docker-образа сервиса.
*   `pyproject.toml`: Определение зависимостей проекта (используется `uv`).
*   `tests/`: **(Требует реализации)** Директория для модульных и интеграционных тестов.

**Отсутствующие компоненты (Требуется реализация):**

*   Интеграция с MongoDB (использование Motor).
*   Реализация логики публикации задач в очередь сообщений для `Pipeline Worker`.
*   Обработка загрузки файлов.
*   Модульные и интеграционные тесты.
*   Обновление документации (`/docs`) в соответствии с реализованной функциональностью.

## Запуск с использованием Docker

1.  **Сборка образа:**
    ```bash
    docker build -t courses-service .
    ```
2.  **Запуск контейнера:**
    ```bash
    # Пример запуска на порту 8002
    docker run -p 8002:8000 -d --name courses_service_app courses-service
    ```
    *Примечание: В `Dockerfile`  используется порт 8000 внутри контейнера.*
