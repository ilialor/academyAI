# Pipeline Worker Service

Фоновый обработчик (worker) для асинхронных задач конвейера обработки контента в AcademyOpenAI.

## Назначение сервиса (согласно архитектуре)

Сервис `pipeline_worker` отвечает за выполнение длительных и ресурсоемких задач по преобразованию контента, сняв нагрузку с основного API (`courses_service`). Его основные функции:

*   **Потребление задач:** Слушает очередь сообщений (например, RabbitMQ или Redis, настроенный через Celery) на наличие новых задач (`process_video_task`, `process_text_task`).
*   **Обработка контента:** Выполняет шаги конвейера:
    *   **Для видео:**
        *   **Вариант А (Прямой):** Вызов мультимодальной LLM (Gemini) для генерации курса напрямую из видео.
        *   **Вариант Б (Многоэтапный):** Извлечение аудио (FFmpeg), преобразование речи в текст (STT API, например, Whisper), перевод (Translation API), генерация структуры курса (LLM).
    *   **Для текста:**
        *   (Опционально) Перевод текста.
        *   Генерация структуры курса и интерактивности (LLM).
*   **Взаимодействие с внешними API:** Общается с API STT, перевода и LLM.
*   **Обновление статуса и результатов:** Сообщает `courses_service` о прогрессе и результатах обработки (например, через API или обновляя общую базу данных MongoDB).

**Входные данные:**
*   Сообщения (задачи) из очереди сообщений, содержащие ID курса и информацию о контенте (путь к файлу, текст).

**Выходные данные:**
*   Запросы к внешним API (STT, Translation, LLM).
*   Обновления статуса/результатов в `courses_service` или MongoDB.
*   Обработанные данные (например, сгенерированная структура курса).

## Текущее состояние проекта

Реализована базовая структура Celery воркера с заглушками для основных компонентов.

**Основные компоненты:**

*   `app/main.py`: Точка входа для запуска Celery воркера.
*   `app/tasks.py`: Определения задач Celery (`process_video_task`, `process_text_task`).
*   `app/processors/video_processor.py`: **(Заглушка)** Логика для обработки видео (прямой и многоэтапный варианты). *Требует реализации взаимодействия с ffmpeg, STT, Translation API.*
*   `app/processors/text_processor.py`: **(Заглушка)** Логика для обработки текста. *Требует реализации опционального перевода.*
*   `app/services/llm_service.py`: **(Заглушка)** Сервис для взаимодействия с LLM (Gemini). *Конфигурирует клиент, но логика вызова API - заглушка.*
*   `app/core/config.py`: Конфигурация воркера (настройки Celery, ключи API, URL сервисов).
*   `Dockerfile`: Файл для сборки Docker-образа воркера.
*   `pyproject.toml`: Зависимости проекта (включая `celery`, `google-generativeai`).
*   `tests/`: **(Требует реализации)** Директория для тестов.

**Отсутствующие компоненты (Требуется реализация):**

*   Реальная логика взаимодействия с FFmpeg для извлечения аудио.
*   Реализация клиентов/сервисов для STT и Translation API.
*   Реальная логика вызовов LLM API в `llm_service`.
*   Реализация механизма обновления статуса/результатов в `courses_service` или MongoDB.
*   Обработка ошибок и логирование.
*   Модульные и интеграционные тесты.
*   Обновление документации (`/docs`) в соответствии с реализованной функциональностью.

## Запуск с использованием Docker

1.  **Убедитесь, что запущены зависимости:** Redis (или другой брокер Celery) и, возможно, MongoDB.
2.  **Настройте переменные окружения:** Создайте файл `.env` в корне `pipeline_worker` или передайте переменные при запуске Docker (например, `GOOGLE_API_KEY`, `CELERY_BROKER_URL`, `MONGODB_URL` и т.д., см. `app/core/config.py`).
3.  **Сборка образа:**
    ```bash
    docker build -t pipeline-worker .
    ```
4.  **Запуск контейнера:**
    ```bash
    # Пример запуска с использованием .env файла и подключением к сети docker-compose (если используется)
    docker run -d --env-file .env --network=<your_docker_network> --name pipeline_worker_app pipeline-worker
    ```
    *Примечание: Воркер запустится и начнет слушать задачи в очереди, указанной в `CELERY_BROKER_URL`.*
