# Auth Service

Микросервис, отвечающий за аутентификацию, авторизацию и управление профилями пользователей в платформе AcademyOpenAI.

## Назначение сервиса (согласно архитектуре)

Сервис `auth_service` выполняет следующие ключевые функции:

*   **Регистрация пользователей:** Обработка запросов на создание новых учетных записей.
*   **Аутентификация:** Проверка учетных данных пользователя (например, email/пароль) и выдача JWT (JSON Web Tokens) при успешном входе.
*   **Авторизация:** (Предполагается) Может включать логику проверки ролей или прав доступа на основе JWT.
*   **Управление профилями:** Предоставляет API для получения и обновления информации профиля пользователя.
*   **Хранение данных:** Взаимодействует с реляционной базой данных PostgreSQL для хранения учетных записей и профилей пользователей.

**Входные данные:**
*   HTTP API запросы от API Gateway (Kong) для регистрации, входа, получения/обновления профиля.
*   Учетные данные пользователя (email, пароль).
*   JWT токены в заголовках запросов для аутентифицированных эндпоинтов.

**Выходные данные:**
*   HTTP API ответы с данными пользователя, статусом операций.
*   JWT токены (access token, refresh token) при успешном входе.
*   Данные, сохраняемые и извлекаемые из PostgreSQL (информация о пользователях, хешированные пароли, профили).

## Текущее состояние проекта (Предполагаемое)

*Предполагается наличие базовой структуры FastAPI приложения. Необходимо проверить фактическую реализацию.*

**Основные компоненты (Ожидаемые):**

*   `app/main.py`: Точка входа FastAPI приложения.
*   `app/api/v1/endpoints/auth.py`: Эндпоинты для регистрации и входа (`/api/v1/auth`).
*   `app/api/v1/endpoints/users.py`: Эндпоинты для управления профилями (`/api/v1/users`).
*   `app/schemas/`: Pydantic модели для пользователей, токенов, запросов/ответов.
*   `app/services/user_service.py`: **(Требует реализации/проверки)** Логика для работы с пользователями.
*   `app/services/auth_service.py`: **(Требует реализации/проверки)** Логика аутентификации, генерации/валидации JWT.
*   `app/db/session.py`: **(Требует реализации/проверки)** Настройка сессии для работы с PostgreSQL (SQLAlchemy + asyncpg).
*   `app/models/user.py`: **(Требует реализации/проверки)** Модель SQLAlchemy для таблицы пользователей.
*   `app/core/config.py`: Конфигурация приложения.
*   `app/core/security.py`: **(Требует реализации/проверки)** Функции для хеширования паролей, работы с JWT.
*   `Dockerfile`: Файл для сборки Docker-образа.
*   `pyproject.toml`: Определение зависимостей (`uv`).
*   `migrations/`: **(Присутствует)** Директория для миграций базы данных (Alembic).
*   `tests/`: **(Требует реализации)** Директория для тестов.

**Отсутствующие/Требующие реализации компоненты:**

*   Полная реализация логики регистрации, аутентификации, управления профилями.
*   Интеграция с PostgreSQL с использованием SQLAlchemy и asyncpg.
*   Настройка и применение миграций Alembic.
*   Безопасная работа с паролями и JWT.
*   Модульные и интеграционные тесты.
*   Обновление документации (`/docs`) в соответствии с реализованной функциональностью.

## Запуск с использованием Docker

1.  **Сборка образа:**
    ```bash
    docker build -t auth-service .
    ```
2.  **Запуск контейнера:**
    ```bash
    # Пример запуска на порту 8001 
    # Потребуется настроить подключение к PostgreSQL!
    docker run -p 8001:8000 -d \
        -e DATABASE_URL="postgresql+asyncpg://user:password@host:port/dbname" \
        --name auth_service_app auth-service
    ```
    *Примечание: Замените `user:password@host:port/dbname` реальными данными для подключения к PostgreSQL. В `Dockerfile`  используется порт 8000 внутри контейнера.*
